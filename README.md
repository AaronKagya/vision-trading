# Vision Trading — audited research pipeline (Phase 2)

**Status:** Code-audited research project; **NOT** a live trading engine or evidence of profitability.

This is a corrected and extended, testable continuation of `vision-trading (new).zip` from the public GitHub repository `AaronKagya/vision-trading`. It retains the seven named experimental baselines, adds one opt-in numerical-visual fusion candidate, and maintains the Phase 1 causality and evaluation fixes. The original `metrics.json` is retained under `historical_evidence/` only and must **not** be mistaken for a result generated by the corrected code.

## What is inside

| File or directory | Purpose |
| --- | --- |
| `src/data.py` | Validated 15-minute OHLCV data and Binance monthly data importer |
| `src/features.py` | Leak-free trailing 15m / 1h / 4h numerical panels and 3-channel chart images |
| `src/models.py` | Numerical LSTM, CNN, ResNet18, ViT, causal world model, and Phase 2 fusion candidate |
| `src/run_experiments.py` | Seven models, walk-forward folds, embargo, accuracy/trading *proxies*, saved forecasts and optional checkpoints |
| `src/metrics.py` | Probabilistic metrics, block bootstrap, PSR/DSR and explicitly labelled log-P&L proxies |
| `src/report.py` | HTML research report generator |
| `src/analysis.py` | Original descriptive error analysis |
| `src/phase2_eval.py` | Paired fusion-versus-LSTM/visual comparisons, fixed confidence bins and train-derived volatility regimes |
| `run_seeds.py` | Repeat fixed configuration with multiple random seeds |
| `app.py` | Streamlit **historical test** explorer; no live exchange execution |
| `historical_evidence/` | Historical user-provided experiment metrics, preserved without modification |
| `tests/` | Regression tests for causality, market data, metrics, report and a full synthetic end-to-end pipeline |
| `docs/` | Detailed audit, provenance, risk, and experiment instructions |

## Requirements

Use Python 3.10+ (3.11 or 3.12 recommended) and a Python virtual environment. Install CPU-compatible PyTorch (or a correctly matched CUDA wheel on your own GPU) before running GPU experiments. These command examples are intended to be run **in the folder containing this README**:

```bash
python -m venv .venv
source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python -m pytest tests -q
```

Optional extras for pretrained encoders or the dashboard:

```bash
pip install -r requirements-optional.txt
```

### Quick full smoke test (no market data, no internet)

```bash
python -m src.run_experiments \
  --data synthetic_null --n-synth 680 --window 16 --img 32 --K 2 \
  --folds 1 --epochs 1 --bs 16 --bootstrap 20 --out results_smoke
python -m src.report --results results_smoke
python -m src.analysis --results results_smoke --bootstrap 20
```

This smoke configuration is *not comparable* to the original research configuration and is **only** used to establish that the code runs end-to-end. Results are stored under `results_smoke/`.

### Phase 2 research protocol and fusion candidate

The original seven models remain the default (`--models all`). The new candidate is selected explicitly with `--models phase2` (eight models, correctly accounted for in the trial count). The fusion architecture processes the **same candles as numbers and images**, with a training-only scaler. It cannot add new raw market information, but may change the features the learner can use.

Run `python -m src.phase2_eval --results results_phase2 --data data/BTCUSDT_15m.csv` after a completed Phase 2 evaluation to generate `phase2_diagnostics.json`. This report contains **descriptive** fold, confidence and train-calibrated volatility analysis; it must not be used to select a winning threshold on the test set.

**See [docs/PHASE2_EXPERIMENT.md](docs/PHASE2_EXPERIMENT.md) for the full predeclared Phase 2 protocol, exact commands, and the later Volatility 75 plan.**

### Historical-data run matching the original experimental parameters

```bash
# One way to acquire the original timeframe, subject to data availability and usage terms
python -c "from src.data import download_binance; download_binance('BTCUSDT','15m','2024-01','2024-12')"

# Original config: seed=0, horizon=4, 3 views, image 64px, 4 folds, 10 epochs
python -m src.run_experiments \
  --data data/BTCUSDT_15m.csv --window 32 --img 64 \
  --horizon 4 --K 6 --folds 4 --epochs 10 --bs 128 \
  --encoder cnn --lr 0.001 --lam 0.5 --cost 0.0005 \
  --seed 0 --bootstrap 1000 --save-checkpoints --out results

python -m src.report --results results
python -m src.analysis --results results --data data/BTCUSDT_15m.csv
```

**Important:** The exact raw dataset used to produce the historical JSON was not supplied. Downloading a similarly named period may not reproduce the original 17,308 test observations because of date coverage, versioning, missing bars, and preprocessing differences. Compare timestamps, number of rows, and SHA-256 stored in corrected output. The CNN/world-model code and image scaler have intentionally changed, so old performance numbers should NOT be expected to reproduce exactly.

### Inspect predictions and model artifacts

```bash
python -m src.report --results results
streamlit run app.py
```

`results/preds.npz` stores out-of-sample prediction probabilities and candle indices, `results/metrics.json` the fold structure and summary metrics, and `results/analysis.json` descriptive diagnostics. With `--save-checkpoints`, per-fold PyTorch checkpoints are written into the results folder. Checkpoints are experimental artifacts only; this version does not expose a production forecasting API.

## Critical scientific distinctions

1. Chart images are **deterministic transformations** of the same OHLC series. They contain no additional raw price information. The legitimate research hypothesis is whether a visual *representation* provides a better inductive bias for prediction.
2. World-model direction forecasts at index `t` now consume only the last `K` chart frames ending at `t`. The image at `t+1` is used solely as an auxiliary training target, independently from the forecast input, with batch normalization frozen for the target pass.
3. `total_return` is kept as a **legacy alias** to the sum of approximated linearized net log-P&L; it is **not** an executable simple return. `implied_compounded_return = exp(total_log_pnl_proxy)-1` is explanatory only. The backtest omits actual funding, borrow, spreads, liquidation, order fills and margin effects.
4. `n_trades` is a legacy count of nonoverlapping sampled evaluation intervals; it is not an order count.
5. The CSV is validated for duplicates, missing intervals, invalid timestamps, price positivity, invalid OHLC, and nonfinite values.
6. The historical test is a backtest, not forward paper trading or live trading.

## Known limitations

- The Binance downloader requires network access and permissive data access terms. Neither network availability nor the exact original market CSV is guaranteed.
- GPU runs can vary with CUDA/PyTorch versions and hardware; software metadata and the source file SHA-256 are recorded.
- The DSR implementation is an approximation of selection correction, not a guarantee against hidden experiment selection or serial dependence.
- Deep-learning outcomes on a tiny synthetic smoke test do not measure skill. **Do not use this code to place trades.**
